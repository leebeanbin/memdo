# 공통 용어집과 정규 규칙

모든 기획, 디자인, 코드, API, 테스트는 이 용어를 사용한다.

## 1. 제품 용어

| 한글 | 코드 용어 | 정의 |
|---|---|---|
| 오늘 | Day | 사용자 타임존의 현지 날짜 |
| 오늘의 계획 | DailyPlan | 날짜별 의도·분위기·회고 컨테이너 |
| 일정 항목 | ScheduleEntry | 캘린더에 표시되는 시간 일정 또는 할 일의 상위 표현 |
| 시간 일정 | Event | 시작·종료 기간이 중심이며 완료 상태를 요구하지 않는 항목 (`entryKind=event`) |
| 할 일 | Task | 사용자가 완료 상태를 결정하는 항목 (`entryKind=task`) |
| 마감일 | dueAt | 할 일의 선택 속성. 별도 유형이나 엔터티가 아님 |
| 반복 규칙 | ScheduleRule | 미래 Todo를 생성하는 RRULE 기반 규칙 |
| 하루 요약 | DailyReview | 정한 시간에 당일 미완료 Todo를 확인하는 규칙 기반 흐름 |
| 요약 응답 | ReviewResponse | 일정 하나에 대한 명시적 사용자 답 |
| 브리핑 | DailyBriefing | 일정과 별개이며 사용자의 브리핑 키워드로 찾은 정보 묶음 |
| 브리핑 키워드 | BriefingKeyword | 뉴스 검색과 후보 정렬에 사용하는 사용자 입력 검색어 |
| AI 계획 초안 | PlanDraft | 승인 전이며 실제 Todo가 아닌 제안 |
| 위젯 스냅샷 | WidgetSnapshot | 위젯 표시용 최소 데이터 |
| 하루의 분위기 | Mood | 집중·여유·활기·회복·설렘 중 사용자 선택 |
| 오늘의 의도 | Intention | 사용자가 원하는 하루를 표현한 짧은 문장 |

## 2. 금지하거나 피할 표현

| 피할 표현 | 사용할 표현 | 이유 |
|---|---|---|
| 실패한 일정 | 건너뛴 일정 / 아직 정리하지 않은 일정 | 평가적 표현 방지 |
| AI가 완료를 감지 | 사용자에게 완료 여부 확인 | 실제 동작과 불일치 |
| 자동 완료 | 완료 응답 반영 | 사용자 결정권 |
| 생산성 점수 | 오늘의 기록 | 제품 정체성 |
| 마일스톤 | 마감일 / 시간 일정 / 할 일 | 의미에 맞는 기존 모델 사용 |
| 일일 리포트 | 하루 요약 | 사용자-facing 정규 명칭 |

## 3. Todo 상태

| 값 | 의미 | 진입 주체 |
|---|---|---|
| planned | 아직 처리되지 않은 계획 | 생성 시스템 |
| in_progress | 사용자가 시작했다고 표시 | 사용자 |
| partial | 사용자가 일부 완료했다고 표시 | 사용자 |
| completed | 사용자가 완료했다고 표시 | 사용자 |
| skipped | 사용자가 해당 실행을 건너뜀 | 사용자 |
| rescheduled | 다른 날짜나 시간으로 새 일정 생성 | 사용자 흐름 |
| cancelled | 일정 자체를 취소 | 사용자 |

시간 경과만으로 상태를 변경하지 않는다.

## 4. 하루 화면 상태

| 값 | 계산 |
|---|---|
| needs_planning | 활성·완료 Todo가 없고 다시 계획할 수 있음 |
| planned | 당일 Todo가 있고 미완료 항목이 있음 |
| completed | 당일 Todo가 있었고 정리 대상이 없음 |

삭제 이력만 있고 활성·완료 Todo가 없으면 `needs_planning`이다. 완료 Todo가 하나라도 남아 있으면 `completed`다. 삭제된 Todo는 상태 계산에서 제외한다.

## 5. 시간 규칙

- `scheduledDate`는 사용자 타임존 기준의 의미상 날짜다.
- `startAt`, `endAt`은 타임존 오프셋이 포함된 ISO 8601이다.
- 사용자 설정에는 IANA 타임존을 저장한다.
- 시간이 없으면 `timeBucket`을 사용한다.
- `isAllDay=true`이면 `scheduledDate`가 표시 기준이며 시간 UI를 숨긴다.
- `entryKind=event`는 `startAt`, `endAt`을 요구한다.
- `entryKind=task`는 시작·종료 기간과 `dueAt`을 선택적으로 가질 수 있다.
- `dueAt`은 Task에서만 허용한다.
- 서버와 앱은 날짜 경계를 UTC가 아닌 사용자 타임존으로 계산한다.

## 6. AI 규칙

- Draft는 Todo가 아니다.
- `commit` 성공 후에만 Todo가 된다.
- AI는 완료 상태를 변경하지 않는다.
- AI는 허용된 동의 범위 밖의 데이터를 받지 않는다.
- 반복 규칙은 승인 후 규칙 엔진이 실행하며 매번 AI가 판단하지 않는다.

## 7. 식별자와 멱등성

- 서버 엔터티 ID는 UUID다.
- 생성과 상태 변경 요청은 `Idempotency-Key`를 사용한다.
- 재예약으로 생성된 Todo는 새 UUID를 갖는다.
- 원본과 새 일정은 `rescheduledFromId`로 연결한다.

## 8. 문서 식별자

```text
PRD-###  제품 요구사항
ADR-###  아키텍처·제품 결정
UX-###   화면 또는 사용자 흐름
DATA-### 데이터 규칙
API-###  API 계약
PRIV-### 개인정보 규칙
TEST-### 검증 시나리오
```

새 기능은 최소 하나의 PRD ID와 TEST ID를 가져야 한다.
