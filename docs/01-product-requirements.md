## 1. 목표

기존 캘린더의 복잡한 업무 관리 대신 사용자가 `오늘을 어떻게 보내고 싶은지` 표현하고 실행과 회고까지 이어지게 한다.

## 2. 대상 사용자

- 계획을 세우고 싶지만 빈 캘린더에서 시작하기 어려운 사람
- 정확한 시간표보다 오전·오후·저녁 단위의 느슨한 계획을 선호하는 사람
- 일정 완료 처리를 자주 잊는 사람
- 개인 취향이 반영된 테마와 위젯을 원하는 사람
- 키워드 기반 브리핑과 오늘 일정을 한 화면에서 보고 싶은 사람

## 3. 핵심 사용자 여정

### 3.1 계획이 없는 아침

1. 사용자가 앱 또는 잠금화면 위젯을 연다.
2. 오늘 일정이 없으면 “오늘은 어떤 하루를 보내고 싶으신가요?”를 표시한다.
3. 사용자는 직접 추가하거나 화면 하단 Agent에 자연어로 요청한다.
4. Agent 초안은 확인 전까지 저장되지 않는다.
5. 승인 후 오늘 화면과 위젯을 갱신한다.

### 3.2 하루 요약

1. 사용자가 온보딩 또는 설정에서 요약 시간을 정한다.
2. 해당 시간에 로컬 알림을 보낸다.
3. 완료되지 않은 일정이 있으면 “이 일은 어떻게 되었나요?”를 표시한다.
4. 사용자가 완료·일부 완료·건너뜀·내일로 이동·시간 변경 중 하나를 선택한다.
5. 모든 응답 후 오늘의 간단한 결과를 보여준다.

### 3.3 반복 계획

1. 사용자가 반복 일정과 알림을 등록한다.
2. 반복 규칙에 따라 일정 인스턴스를 생성한다.
3. 지정된 시간에 알림을 보낸다.
4. 하루 요약에서 미완료 상태를 확인한다.

### 3.4 브리핑 키워드 기반 뉴스

1. 사용자가 직접 입력하거나 제안 목록에서 브리핑 키워드를 최대 5개 고른다.
2. 브리핑을 요청하거나 자동 브리핑을 허용한다.
3. 최신 기사 3~5개를 출처·게시 시각·원문 링크와 함께 제공한다.
4. 잠금화면에는 민감한 기사 제목 대신 “오늘의 브리핑 4개”를 기본 표시한다.

## 4. 기능 요구사항

### P0 — MVP 필수

| ID | 요구사항 |
|---|---|
| PRD-001 | 제목과 날짜만으로 일정을 저장할 수 있어야 한다. |
| PRD-002 | 시간 없는 일정을 오전·오후·저녁·언제든으로 분류할 수 있어야 한다. |
| PRD-003 | 오늘 일정이 없으면 계획 시작 질문을 표시해야 한다. |
| PRD-004 | 사용자가 하루 요약 시간을 설정·변경·비활성화할 수 있어야 한다. |
| PRD-005 | 하루 요약에서 미완료 일정만 확인해야 한다. |
| PRD-006 | 완료 상태는 사용자 응답으로만 확정해야 한다. |
| PRD-007 | 완료·일부 완료·건너뜀·내일로 이동·시간 변경을 지원해야 한다. |
| PRD-008 | 반복 일정을 생성·수정·중지·삭제할 수 있어야 한다. |
| PRD-009 | 일정별 알림 시간을 설정할 수 있어야 한다. |
| PRD-010 | 잠금화면 위젯 탭 후 앱의 대응 화면으로 이동해야 한다. |
| PRD-011 | 앱과 위젯이 동일한 오늘 상태를 표시해야 한다. |
| PRD-012 | 알림 거부 상태에서도 앱이 정상 동작해야 한다. |
| PRD-013 | AI 계획은 승인 전까지 실제 일정에 반영하면 안 된다. |
| PRD-014 | 개인정보 동의는 목적과 데이터 범위별로 분리해야 한다. |
| PRD-015 | 항목을 `시간 일정(EVENT)` 또는 `할 일(TASK)`로 저장하고 캘린더에서 유형·출처별로 필터해야 한다. 할 일의 마감은 별도 유형이 아닌 `dueAt` 속성이다. |
| PRD-016 | Agent는 독립 탭이 아니라 오늘·캘린더·설정 어디서나 접근할 수 있어야 하며, 일정 생성·수정은 사용자 승인 후에만 실행해야 한다. |

| PRD-104 | 여러 기기 간 일정과 설정을 동기화한다. |
| PRD-105 | 주간 완료 패턴을 보여주되 평가하거나 꾸짖지 않는다. |
| PRD-106 | Google Calendar를 최소 권한으로 연결하고 읽기 전용 미러를 동기화한다. |

| PRD-108 | 외부 AI 변경은 제안 링크에서 사용자가 승인한 뒤 실행한다. |

## 5. 비기능 요구사항

- 오늘 화면은 로컬 데이터로 1초 안에 표시한다.
- 네트워크 장애 중에도 일정 생성·수정·완료가 가능해야 한다.
- 모든 서버 테이블에 사용자 단위 접근 통제를 적용한다.
- API 키와 외부 서비스 토큰을 앱 번들에 저장하지 않는다.
- 위젯 개인정보 숨김 설정을 제공한다.
- 날짜 계산은 사용자 IANA 타임존을 기준으로 한다.
- 알림 전달은 운영체제 정책상 보장되지 않음을 UI에서 오해 없이 표현한다.

## 6. 범위 제외

- 참석자, 회의실, 조직용 권한
- 간트 차트와 프로젝트 자원 관리
- 센서나 위치로 완료 여부 추측
- 승인 없는 AI 일정 삭제
- 무제한 자유 배치 UI 편집기
- 초기 버전의 다중 Agent 및 자체 MCP

## 7. 제품 지표

- 온보딩 후 24시간 이내 첫 계획 생성률
- 하루 요약 시간 설정률
- 하루 요약 알림 열람률
- 미완료 일정 응답률
- 내일로 이동 후 다음 날 완료율
- AI 초안 승인·수정·폐기 비율
- 알림 및 AI 동의 철회율
