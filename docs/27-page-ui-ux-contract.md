# 페이지별 UI/UX 계약

상태: iPhone 15 구현 기준선
기준일: 2026-08-09
상위 문서: [제품 요구사항](./01-product-requirements.md), [결정 기록](./10-decisions-and-open-questions.md)
구현 토큰·컴포넌트: [iOS 디자인 기준선](../apps/ios/Memdo/DESIGN.md)
밀도·카드·Agent UI: [디자인 시스템·밀도·Agent UI 계약](./28-design-system-density-and-agent-ui.md)

이 문서는 각 화면의 정보 위계, 조작, 전환, 필드, 빈 상태를 고정한다. 구현과 API에서 다른 이름을 만들지 않는다.

## 1. 제품 표현 원칙

- 앱은 `Native shell / Memdo content` 구조를 따른다. 탭바·툴바·검색·시트·메뉴·피커·토글은 Apple 네이티브 문법을 우선하고, 캘린더 그리드·일정 행·브리핑·오늘 요약·Agent 변경안이 Memdo의 제품 정체성을 담당한다.
- Apple UI를 닮게 만드는 별도 커스텀 셸을 만들지 않는다. 최신 시스템에서 자동으로 갱신되는 SwiftUI 컴포넌트를 사용하고, 지원하는 이전 OS에서는 같은 컴포넌트의 시스템 표현을 유지한다.
- Notion Calendar처럼 기본 화면은 조용하고, 세부 기능은 메뉴·시트 안에 둔다.
- Google Calendar처럼 생성은 빠르게 시작하되 날짜와 시간은 시스템 picker로 정확히 입력한다.
- Agent는 별도 목적지가 아니라 사용자가 일정을 보고 쓰는 모든 순간의 보조 계층이다.
- 기본 면은 시스템 semantic 흑백으로 구성하고 보랏빛 브랜드 색은 로고·eyebrow·할 일·Agent 근거에만 쓴다.
- 한 화면의 전면 주요 행동은 하나다. 파괴 행동은 `…` 메뉴와 확인 대화상자 안에 둔다.
- 텍스트 버튼의 시각 높이는 28–32pt로 작게 보일 수 있지만 실제 터치 영역은 최소 44×44pt다.
- Glass는 시스템 탭바와 검색 입력기처럼 떠 있는 조작 계층에만 쓴다. 본문 카드는 불투명 semantic surface다.
- 4개 이상 일정은 첫 3개와 `나머지 N개 보기`만 먼저 보여준다. 오늘 화면을 약 120pt 위로 스크롤하면 바가 자동으로 펼쳐지고, 버튼으로 직접 펼치거나 접는 동작도 유지한다.

## 2. 정규 일정 모델

`마일스톤`은 제품 유형이 아니다. 사용자의 의도에 따라 다음 둘 중 하나를 선택한다.

| 사용자 표현 | 코드/API | 필수 시간 의미 | 완료 | 마감 |
|---|---|---|---|---|
| 시간 일정 | `event` | `startAt`, `endAt` | 없음 | 없음 |
| 할 일 | `task` | 시간 배정 시 `startAt`, `endAt` | 사용자만 변경 | 선택 `dueAt` |

- `dueAt`은 Task의 속성이지 별도 카드·엔터티·필터 유형이 아니다.
- 하루 종일 여부는 Boolean이므로 `Toggle`을 사용한다.
- 유형 선택은 상호 배타적이지만 작은 설정 행이므로 큰 segmented control 대신 시스템 Menu Picker를 사용한다.
- 날짜·시각·기간은 자유 텍스트로 입력하지 않는다.
- Event에 `dueAt`을 저장하지 않는다.
- Task 완료율과 오늘 요약의 미완료 질문에는 Event를 포함하지 않는다.

## 3. 앱 셸

하단에는 세 개의 콘텐츠 탭과 하나의 Agent 액션이 있다.

```text
오늘 | 캘린더 | 설정 | Agent
```

| 탭 | 사용자가 답하려는 질문 |
|---|---|
| 오늘 | 지금 무엇을 하고, 오늘을 어떻게 마무리할까? |
| 캘린더 | 특정 날짜에 무엇이 있고 언제 비어 있을까? |
| 설정 | 언제 알림을 받고 어떤 정보 접근을 허용할까? |

Agent는 별도 페이지가 아니다. 네 번째 시스템 탭 위치와 같은 실제 프레임의 액션 영역이 직전 콘텐츠 탭을 유지한 채 Agent 시트를 직접 연다. 탭을 선택했다 되돌리거나 콘텐츠 위 플로팅 버튼을 사용하지 않는다.

앱 셸은 `TabView`, `NavigationStack`, 시스템 toolbar, `searchable`, `sheet`, `Menu`, `confirmationDialog`, `Form`, `List`, `Picker`, `DatePicker`, `Toggle`을 먼저 검토한다. 이 컴포넌트가 해결하는 동작을 외형 때문에 다시 구현하지 않는다. 커스텀 셸은 네이티브 API로 표현할 수 없는 제품 고유 콘텐츠가 있고 사용자 이점이 검증된 경우에만 ADR을 추가한 뒤 허용한다.

최상위 탭을 좌우 스와이프로 바꾸지 않는다. 그 제스처는 날짜·월 이동 및 시스템 뒤로가기에 남겨 둔다.

## 4. Agent

### 탭 액션

```text
Agent
```

- 탭하면 `.medium/.large` detent의 Agent 시트가 열린다.
- 기본 카드 수는 0개이며, 하단 고정 composer와 열린 행을 사용한다.
- 빠른 요청 3개는 빈 상태에서만 보이고 응답 뒤에는 결과에 공간을 양보한다.
- 시트를 닫아도 작성 중인 요청과 응답은 앱 세션 동안 유지한다. 초기화는 상단 `새 대화`를 사용자가 직접 눌렀을 때만 한다.
- 오늘에서는 요약·새 일정·미완료 정리를 제안한다.
- 캘린더에서는 빈 시간·충돌·할 일 배치를 제안한다.
- 설정에서는 권한·요약 시간·자동화 실행 범위를 설명한다.

### 실행 계약

1. 읽기와 설명은 허용된 동의 범위 안에서 즉시 수행한다.
2. 일정 생성·수정·삭제는 구조화된 변경안으로 만든다.
3. 변경 전 제목·시작·종료·마감·알림·반복을 보여준다.
4. 사용자가 승인한 뒤에만 commit한다.
5. 실패하면 입력과 변경안을 유지하고 재시도를 제공한다.

노트의 `Agent` 메뉴는 `문장 정리`, `할 일로 나누기`, `준비물 제안`을 제공한다. 결과는 노트 필드에 먼저 반영되어 사용자가 직접 고치거나 취소할 수 있다.

## 5. 오늘

### 첫 화면 위계

```text
날짜 맥락 + 할 일 완료 현황
→ 7일 날짜 레일
→ 선택 날짜의 일정 또는 빈 날 질문
→ 오늘의 브리핑
```

### 표시 필드

| 영역 | 필드 |
|---|---|
| 헤더 | 오늘/선택 날짜, 요일, 완료한 Task/전체 Task |
| Event 행 | 왼쪽 시작·종료 시간축, 제목, 캘린더, 출처 |
| Task 행 | 왼쪽 완료 원, 제목, 마감 또는 배정 시간, 캘린더, 출처 |
| 브리핑 | 순번, 제목, 출처·게시 시각·선정 이유 |

### 행동

- 날짜 탭: 모달 없이 해당 날짜의 일정으로 교체한다.
- 7일 날짜 레일을 좌우로 스와이프: 범위 안에서 이전·다음 날짜로 이동한다. 일정 행에서는 스와이프를 받지 않는다.
- 일정 행 탭: 읽기 전용 상세 시트를 연다.
- Task 완료 원 탭: 완료/미완료를 전환한다. Event에는 완료 원이 없다.
- 헤더 완료 현황 링 탭: 오늘 요약 시트를 연다. 같은 목적의 하단 요약 카드는 두지 않는다.
- `새 일정`: 선택 날짜가 채워진 추가 시트를 연다.
- 날짜 아래의 점 1~3개로 일정 밀도를 표현하고, 정확한 미완료 개수는 VoiceOver 값으로 제공한다. 완료한 Task는 밀도에서 제외한다.
- 일정이 4개 이상이면 첫 3개만 보이고 스크롤을 내릴 때 자동으로 펼친다. 사용자가 직접 접은 뒤에는 화면 상단으로 돌아오기 전까지 자동으로 다시 펼치지 않는다.

### 상태

| 상태 | 표현 |
|---|---|
| 일정 없음 | “오늘은 어떤 하루를 보내고 싶나요?” + 직접 추가 |
| 1–3개 | 전부 표시 |
| 4개 이상 | 3개 + 나머지 개수 |
| 과거 날짜 | 당시 항목과 완료 기록 표시 |
| Task 모두 완료 | 100% 표시, 강한 축하 모달 없음 |

## 6. 캘린더와 검색

### 기본 위계

```text
캘린더 제목 + 검색
→ 월·필터·오늘
→ 올바른 요일 오프셋의 월간 그리드
→ 선택 날짜 일정
```

- 날짜 한 번 탭: 선택만 바꾸고 아래 목록을 교체한다.
- 날짜 길게 누르기: 해당 날짜 전체 일정 시트를 연다.
- 월 헤더를 좌우 스와이프: 이전·다음 달로 이동한다. 날짜 그리드에서는 탭·길게 누르기만 받는다.
- 일정이 있는 날짜는 미완료 항목 개수, 선택 날짜는 채운 원으로 표시한다. 완료한 Task는 개수에서 제외한다.
- 필터가 켜지면 날짜 점·목록·개수를 같은 결과 집합으로 계산한다.
- VoiceOver에는 이전/다음 달과 하루 일정 열기 custom action을 제공한다.

필터는 다음을 제공한다.

```text
전체 | 시간 일정 | 할 일 | 개인 | 업무 | 내 일정 | Google
```

검색은 별도 탭이 아니다. 헤더 돋보기를 누르면 Glass 검색 입력과 `전체/내 일정/Google` 범위를 펼친다. 닫을 때 검색어와 결과를 지우고 월간 캘린더로 돌아간다. 제목·노트·장소를 검색하며 완료 상태·기간은 상세 필터 시트에서 좁힌다.

검색 결과를 위한 별도 AI 요약 카드·시트는 두지 않는다. 자연어 분석이 필요하면 현재 캘린더 문맥을 유지하는 공통 Agent를 사용한다.

## 7. 일정 추가·상세·수정

### 추가·수정 필드 순서

```text
[기본 정보]
제목
분류 Menu
  유형: 시간 일정 / 할 일
  캘린더: 개인 / 업무 / 연결된 외부 캘린더 / 사용자 캘린더 추가
하루 종일

[언제]
날짜: 시스템 DatePicker
시간: 시작·종료 시스템 DatePicker를 한 행에 표시
여러 날: 필요할 때만 종료 날짜를 펼침
마감: 시스템 DatePicker (할 일에서 선택 추가)

[선택 정보]
장소: 시스템 지도 검색, 저장 후 Google 지도 열기 지원
알림
반복: 안 함 / 매일 / 평일 / 매주 / 2주 / 매월 / 매년

[노트]
멀티라인 입력
Agent 메뉴
```

- `endAt > startAt`을 앱과 서버에서 검증한다.
- 시작을 종료 이후로 바꾸면 종료를 같은 기간만큼 이동시키거나 즉시 오류를 설명한다.
- Task에서 `마감일 추가`를 누른 경우에만 due picker를 표시한다.
- 저장은 제목이 비었거나 시간 순서가 잘못되면 비활성화한다.

### 상세

- 기본은 읽기 전용이다.
- 상단 `수정` 후에만 동일한 공통 편집 필드를 사용한다.
- Task만 작은 완료 Toggle을 보여준다.
- `닫기/수정`은 편집 중 `취소/저장`으로 바뀐다.
- 취소는 마지막 저장 값으로 복구하고, 저장은 Store의 단일 `save` 경로를 사용한다.

## 8. 오늘 요약

오늘 요약은 앱 내부 시트이고 시스템 알림은 진입점이다.

```text
오늘 / 7일 / 30일 범위
→ 완료 수 · 확인 또는 놓침 수 + 진행선
→ Agent의 근거 기반 해석과 대화 진입
→ 오늘은 결정이 필요한 Task, 지난 기간은 완료·놓침 Task
```

- 큰 그래프·점수·평가 문구를 사용하지 않는다.
- 지난 7일과 지난 30일은 오늘을 제외한 완료된 날짜만 집계한다.
- Agent 해석은 실제 완료·미완료 Task 제목을 근거로 사용하고 같은 기간 문맥으로 Agent 시트를 연다.
- 지난 기간은 `잘 끝낸 작업`과 `놓치고 지난 작업`을 분리하며 각 목록은 처음 3개 후 펼친다.
- 미완료 행의 전면 행동은 왼쪽 완료 원과 오른쪽 `calendar.badge.clock` 아이콘이다. 아이콘은 내일 이동을 실행하고 VoiceOver에서 동작을 문장으로 읽는다.
- 다른 날짜 이동은 `…` 메뉴에서 시스템 DatePicker 시트를 열어 확정한다.
- 삭제는 `…` 메뉴와 확인 대화상자를 거친다.
- 하단 완료 버튼을 반복하지 않는다. 닫기는 헤더 `xmark`와 시스템 sheet 제스처가 담당한다.
- Event는 완료 질문과 지난 기간 완료율에서 제외한다.
- 해결한 행은 즉시 사라지고 개수가 갱신된다.

## 9. 오늘의 브리핑

- 목적은 약 1분 안에 오늘 알아둘 정보만 확인하는 것이다. 일반 조언·회고는 Agent 제안으로 분리한다.
- 기본 구성은 브리핑 키워드 뉴스 2개와 일정 영향 정보 최대 1개이며 전체는 기본 3개, 최대 5개다.
- 오늘 화면에는 작은 `AI 요약` 출처 표시, 변화와 의미를 연결한 22~36자의 편집형 헤드라인 최대 두 줄, `대표 출처 외 N개 · 1분` 메타데이터로 구성한 평면 preview만 둔다.
- preview를 누르면 시트에서 3개, 관심사가 충분하면 최대 5개 headline row를 보여준다.
- 각 행은 제목을 먼저, 출처·게시 시각·선정 이유를 한 줄 메타데이터로 표시한다.
- 큰 썸네일과 뉴스 앱형 hero card는 사용하지 않는다.
- 상세 시트에서 요약·출처·게시 시각·원문 링크·선정 이유를 제공한다.
- 브리핑은 일정과 섞지 않으며 Agent가 사용자가 고른 키워드를 바탕으로 조용히 정리한 결과로 표현한다.
- 출처 URL 없는 뉴스, 중복 기사, 24시간이 지난 일정 영향 정보는 노출하지 않는다.
- 정렬은 일정 영향도 → 관심사 관련성 → 최신성 → 주제 다양성 순서다.
- 일정 변경 제안은 직접 실행하지 않고 Agent 변경안 확인으로 연결한다.

## 10. 설정과 동의

위계는 `하루 → 내 Agent 연결`이다. 브리핑 키워드는 하루 그룹의 상태 행에서 편집하고 개인정보는 Agent 연결 그룹의 데이터 관리 행에서 연다.

| 구역 | 항목 |
|---|---|
| 하루 | 오늘 요약 사용, 요약 시간, 계획이 없을 때 묻는 시간 |
| 내 Agent 연결 | Google Calendar·Slack MCP 도구, Agent 데이터 범위, 데이터 관리 |
| 브리핑 키워드 | 직접 입력하거나 제안에서 고른 검색어 최대 5개 |
| 개인정보 | 보관, 철회, Agent 실행 기록 삭제 |

- 시간은 시스템 picker를 쓴다.
- Google과 Slack은 OAuth 전 `연결 안 됨`으로 표시하며 Toggle로 연결 상태를 흉내 내지 않는다.
- Google Calendar와 Slack은 공식 제품 마크, Agent가 사용하는 능력, 연결 상태를 같은 행에 표시한다. `MCP`는 설명을 보조하는 작은 텍스트 배지이며 색만으로 연결 여부를 표현하지 않는다.
- 외부 서비스 상세 시트의 첫 섹션은 해당 도구가 Memdo Agent에 제공하는 능력을 설명하고, OAuth scope와 실행 전 승인 원칙을 이어서 보여준다.
- Slack MVP는 `chat:write`, `channels:read`, `commands`만 기본 요청한다. 일정·요약 전송, 예약 전송, `/memdo add` 초안을 지원하고 채널 기록·DM은 읽지 않는다.
- 브리핑 키워드는 대소문자 무시 중복 제거 후 검색·후보 정렬에만 사용한다.
- Agent 동의는 읽는 필드, 목적, 외부 전송, 보존 기간, 철회 결과를 분리해 보여준다.
- Light/Dark는 MVP에서 시스템 설정을 따른다.
- 설정 그룹은 시스템 grouped surface와 내부 separator로 구분하며, 콘텐츠 행에는 Liquid Glass를 적용하지 않는다.

## 11. 위젯과 알림

| 종류 | 핵심 정보 |
|---|---|
| 잠금화면 inline | 다음 항목 + 남은 개수 |
| 잠금화면 circular | 날짜 또는 Task 완료율 |
| 잠금화면 rectangular | 최대 2개 + N개 더 |
| 홈 small | 오늘 날짜 + 최대 2개 |
| 홈 medium | 주간 인덱스 + 최대 3개 |
| 홈 large | 월간 인덱스 + 오늘 항목 |

- 잠금 상태 개인정보 숨김이면 제목 대신 시간과 개수만 표시한다.
- Event와 Task는 clock/check 아이콘과 텍스트로 함께 구분한다.
- 위젯 탭은 잠금 해제 후 정확한 날짜·상세·추가·요약으로 deep link한다.
- 알림 전달 여부로 완료 상태를 바꾸지 않는다.

## 12. 전환과 모션

| 조작 | 전환 |
|---|---|
| 오늘 좌우 스와이프 | 0.25초 snappy 날짜 교체 |
| 월 좌우 스와이프 | 0.25초 snappy 월 교체 |
| 일정 상세·추가·Agent·요약 | 시스템 sheet |
| 시트 아래로 스와이프 | 시스템 dismiss |
| 저장·완료 | 짧은 success/selection haptic |

Reduce Motion이 켜지면 의미 없는 morph·scale을 제거한다. 제스처로 가능한 모든 행동은 버튼 또는 접근성 action으로도 가능해야 한다.

## 13. 구현 완료 기준

- 기본·빈 상태·4개 이상·오류/권한 상태가 정의되어 있다.
- 같은 행동은 공통 버튼 위계와 공통 시트 표현을 사용한다.
- Light/Dark, Larger Text, VoiceOver 이름, 44pt 터치 영역을 확인한다.
- 탭바·Agent 시트·입력기가 콘텐츠를 가리거나 현재 탭을 불필요하게 바꾸지 않는다.
- 필터·유형·완료 상태를 색만으로 전달하지 않는다.
- Agent와 외부 캘린더는 출처·동의 범위·실행 전 승인을 숨기지 않는다.
- 코드, ERD, OpenAPI, 테스트가 `event/task/dueAt`을 동일하게 사용한다.

## 14. 아직 실제 서비스와 연결되지 않은 영역

- 온보딩과 실제 시스템 권한 요청
- Google OAuth·증분 동기화·충돌 처리
- 서버 검색의 로딩·오프라인·재시도
- 실제 Agent tool call·승인 commit·감사 로그
- 실제 뉴스 출처·게시 시각·원문 링크
- App Group 기반 실데이터 위젯
- 시스템 알림 예약과 실기기 deep link 검증
- 서버 동기화 및 사용자 타임존 전환 테스트
- 확정 로고 에셋
