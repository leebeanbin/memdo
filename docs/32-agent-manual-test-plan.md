# 32. Agent 실사용 테스트 체크리스트

## 이 문서가 존재하는 이유

Agent(온디바이스+클라우드)의 도구별/컨텍스트별 동작을 자동 테스트로 끝까지 검증할 수 없는 두 가지 이유가 있다:

1. **클라우드 경로는 실제 OpenRouter API 키와 과금이 필요하다.** 자동화 테스트가 실제 모델을 호출하게 만들면 매번 비용이 발생하고, CI에서 키를 관리해야 하는 문제가 생긴다.
2. **온디바이스 경로(Apple Intelligence)는 실기기에서만 완전히 신뢰할 수 있다.** 시뮬레이터에서 `SystemLanguageModel.default.availability`가 `.available`을 반환하는 걸 확인했지만(2026-08-20 기준), 실제 응답 품질/속도는 실기기와 다를 수 있다.

그래서 구조적으로 검증 가능한 부분(도구 스키마, `buildScheduleContext()`가 실제로 필요한 정보를 담고 있는지, 프롬프트→도구 매핑)은 `MemdoTests/ScheduleModelTests.swift`의 자동 테스트로 고정했고, **실제 모델이 그 프롬프트를 받아 올바른 도구를 올바른 인자로 호출하는지**는 이 문서를 따라 사용자가 직접 확인해야 한다.

## 실행 전 준비

- **클라우드 경로:** 설정 > 클라우드 Agent에서 OpenRouter API 키를 연결한다.
- **온디바이스 경로:** 실기기에서 설정 > Apple Intelligence를 켠 상태로 실행한다(시뮬레이터도 동작하지만 실기기가 최종 기준).
- 두 경로를 비교하려면 같은 프롬프트를 두 기기(또는 시뮬레이터+실기기)에서 각각 실행한다.

## 확인 방법

각 항목에서: (1) 프롬프트를 그대로 입력 → (2) 화면에 예상한 도구 결과(카드 또는 텍스트)가 뜨는지 → (3) 카드가 뜨는 경우 내용이 실제 일정과 일치하는지 확인한다. 어긋나면 무엇이 어떻게 다른지 기록한다.

## 오늘 (`.today`)

| 프롬프트 | 기대 동작 |
|---|---|
| 오늘 빈 시간에 집중 일정 1시간 추가해줘 | `proposeSchedule`/`propose_schedule` 호출 → 일정 제안 카드(시간 포함) |
| 오늘 일정 핵심만 요약해줘 | 도구 호출 없이 오늘 일정 텍스트 요약 |
| 오늘 끝낸 할 일이 있으면 완료 처리해줘 | 완료되지 않은 할 일이 있다면 `updateSchedule`/`propose_schedule_update`(complete) 호출 → 완료 처리 제안 카드. 이미 완료된 항목만 있으면 "완료 처리할 항목이 없다"는 취지의 응답 |
| (일정이 하나도 없는 날) 오늘 오후 2시에 집중 업무 1시간 일정 추가해줘 | `proposeSchedule` 호출 → 카드 |

## 캘린더 (`.calendar`)

| 프롬프트 | 기대 동작 |
|---|---|
| 이번 주에 1시간 비는 시간 찾아줘 | `findFreeSlots`/`find_free_slots` 호출 → 빈 시간대 나열 |
| 겹치거나 너무 붙은 일정 알려줘 | 도구 호출 없이 컨텍스트 기반 분석(겹치는 시간대 지적) |
| 미완료 할 일을 빈 시간에 제안해줘 | 미완료 할 일 목록 + 빈 시간을 조합한 제안(이상적으로는 `findFreeSlots` 호출 포함) |

## 하루 정리 / 지난 7일 회고 / 지난 30일 회고 (`.todaySummary` / `.weekReview` / `.monthReview`)

동일한 3개 프롬프트 세트를 컨텍스트 이름만 바꿔 사용한다 — `{context}`가 실제로 치환되는지 함께 확인.

| 프롬프트 (예: 지난 7일 회고) | 기대 동작 |
|---|---|
| 지난 7일 회고에서 잘 이어간 작업을 알려줘 | 완료된 항목 중심 분석 |
| 지난 7일 회고에서 놓친 작업의 공통점을 찾아줘 | 미완료 항목의 공통 패턴 분석(제목 목록이 실제로 컨텍스트에 포함돼 있어야 가능 — `buildScheduleContext()`의 `.weekReview`/`.monthReview` 케이스가 이미 이 정보를 포함하도록 고쳐져 있음) |
| 지난 7일 회고 내용을 바탕으로 다음 계획을 제안해줘 | 다음 행동 제안(이상적으로 `proposeSchedule` 호출로 이어질 수 있음) |

## 설정 (`.settings`)

| 프롬프트 | 기대 동작 |
|---|---|
| Agent가 사용하는 정보를 알려줘 | 정적 설명 응답(실제 동의 게이팅과는 아직 무관 — 알려진 한계, 32.md 작성 시점 기준 `AIConsentSheet`에 영속 플래그 없음) |
| 하루 시작과 하루 정리 설정을 설명해줘 | 정적 설명 응답 |
| 반복 일정 실행 전에 무엇을 확인하는지 알려줘 | 정적 설명 응답 |

## 완료/이동/삭제 제안 (모든 컨텍스트, 자유 입력)

빠른 요청 목록에는 없지만 자유 텍스트로 직접 확인해야 하는 시나리오:

| 프롬프트 | 기대 동작 |
|---|---|
| "[실제 일정 제목]" 완료 처리해줘 | `updateSchedule`(온디바이스)/`propose_schedule_update`(클라우드, action=complete) 호출 → 완료 처리 제안 카드. 확인 시 실제로 완료 상태가 바뀌는지 |
| "[실제 일정 제목]" 내일로 옮겨줘 | action=reschedule 호출 → 일정 변경 제안 카드. 옮기려는 시간대에 다른 일정이 있으면 카드에 충돌 경고가 뜨는지 |
| "[실제 일정 제목]" 삭제해줘 | action=delete 호출 → 삭제 제안 카드. 확인 시 실제로 삭제되는지 |
| 존재하지 않는 제목으로 "완료 처리해줘" | 못 찾았다는 응답(카드 없이) — 없는 항목을 있는 것처럼 제안하면 버그 |

## 브리핑 AI 요약 (Agent 탭이 아닌 별도 진입점)

| 동작 | 기대 동작 |
|---|---|
| 브리핑 기사 상세에서 "AI 요약" 버튼 탭 | 온디바이스 모델이 원문 요약을 자연스러운 문장으로 다듬어 표시(사실·숫자는 원문과 동일해야 함) |
